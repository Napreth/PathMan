# PathMan

面向 Windows 的环境变量与程序别名管理器，使用 C# 构建核心、桌面界面、CLI 和后台程序，使用 C++ 实现独立运行的垫片。

> **开发阶段：pre-alpha。** 已提供环境变量编辑、分组、Path 清理预览、变更监控与基础程序别名管理。功能、命令、配置格式与界面仍可能调整。

## 当前进度

已实现：

- CLI 程序别名管理：创建、列出、删除和刷新垫片，同卷直接硬链接，跨卷复制一份本地模板后复用硬链接；透传参数、标准输入输出和退出码。
- 环境变量管理：左侧分别展示用户变量和系统变量，分组可折叠；右侧为等宽的文本框或列表，操作按钮位于内容框外。
- 分号列表：PATH、PATHEXT 以及其他含分号的变量按条目显示，保留顺序、重复项、空项和未展开的 `%变量名%` 引用。
- Win11 Fluent 桌面界面：变量管理、健康检测、程序别名、版本管理、变量监控、关于六项导航，跟随系统浅色／深色主题；标题显示运行权限及管理员操作授权状态，版本管理目前仅提供占位页。
- 变量及分组的新建、重命名和删除；列表条目的新增、编辑、目录浏览、排序及文本编辑。值的编辑先暂存，保存时写入注册表；检测到外部修改时拒绝覆盖，修改系统变量时请求管理员权限。
- 可配置分组：默认路径变量、系统变量、其他变量，启用监控后显示外部变量；支持增加任意数量的自定义分组。
- 行内编辑、置顶与拖拽：变量名在分组标题右侧缩进，行尾提供置顶、编辑和删除；双击或 F2 原地修改名称，列表条目也可原地编辑。选中分组时右侧显示组内变量及其值。
- 递归路径编辑：纯引用可逐层展开，路径条目和引用组可混合排序、移入其他引用组；修改保留原始引用，保存实际所属变量。
- 健康检测与通知：启动和刷新后检查引用回环、未定义变量、系统到用户作用域的引用、注册表类型、展开后的重复项与空条目，以及垫片目录顺序；在原页面查看相关变量和修复操作，支持忽略、删除空行、选择重复项来源及修正类型。
- 桌面程序别名管理：开关控制用户 PATH 中的垫片目录，支持新建、行内重命名、目标编辑、浏览、复制和删除；严格校验别名的 Windows 文件名，目标程序路径允许为空或无效，调用时再报错；未启用时保留选择并禁用编辑操作。
- 外部变更监控：后台记录用户与系统环境变量的新增、修改和删除，将外部变更的变量归入外部分类，区分 PathMan 自身保存。
- 普通后台进程：单实例、启动、停止和状态查询，默认不自启。
- Path 清理：展开引用后去重，将系统 Path 中的软件条目迁移到独立变量；应用前以双栏 diff 预览，保存原始值备份。健康问题集中在健康检测页展示。
- NSIS 安装与卸载：从启动起全局互斥，检测运行中的桌面、后台、CLI 与垫片，提示保存并正常关闭；支持同版本覆盖、版本升级及包类型／架构切换，阻止降级。

后续规划：变量监控工作流、多版本切换。当前 Path 清理由用户手动预览、应用，不随监控自动执行。

## 模块与入口

| 模块 | 语言 / 技术 | 职责 / 入口 |
| --- | --- | --- |
| Pathman.Core | C# / .NET 10 | 环境变量读写、分类与分组配置、变更监控、目录布局、别名管理、后台控制、自启设置，共享类库 |
| Pathman.Gui | C# / WPF | 桌面启动器 `PathMan.exe` |
| Pathman.Cli | C# | 命令行入口 `bin\pathman.exe` |
| Pathman.Service | C# | 用户会话后台程序 `internal\PathMan.Service.exe`，默认不自启 |
| Pathman.Shim | C++20 / Win32 | 通用垫片 `internal\PathMan.Shim.exe` |

`Pathman.Service` 是普通后台 EXE，不注册 Windows 系统服务（因为会话问题）。

## 安装布局

```text
%LocalAppData%\Programs\PathMan\   # 仅为自己安装；所有用户安装默认 %ProgramFiles%\PathMan
├── PathMan.exe                    # 桌面入口
├── LICENSE
├── bin\
│   └── pathman.exe                # bin 只包含 CLI
└── internal\
    ├── PathMan.Service.exe        # 后台程序，无控制台窗口
    ├── PathMan.Shim.exe           # 垫片本体
    ├── PathMan.SetupActions.dll   # 原生安装维护辅助库
    ├── install.ini                # 安装范围
    └── Uninstall.exe              # NSIS 生成的卸载器

%LocalAppData%\PathMan\
├── environment.json               # 分组、分配规则、监控设置及最近的变更记录
└── shims\
    ├── pm-pwsh.exe                # 硬链接 → 程序目录\internal\PathMan.Shim.exe
    └── pm-pwsh.shim               # 这个别名的配置
```

安装目录可以与 LocalAppData 位于不同卷。同卷时别名直接硬链接到安装目录中的垫片；跨卷时在 `%LocalAppData%\PathMan\internal\PathMan.Shim.exe` 保留一份副本，所有别名硬链接到该副本。刷新时校验模板内容、原子替换变化的副本并重新链接别名；已有别名配置保持不变。LocalAppData 所在卷需支持硬链接。
启动位置不能确定安装目录时，读取 `HKCU`／`HKLM` 的 `Software\Microsoft\Windows\CurrentVersion\Uninstall\PathMan\InstallLocation`，兼容 32／64 位注册表视图。安装器也使用卸载登记识别正在运行的复制垫片。
垫片通过自身启动路径定位同名 `.shim`。原生可执行程序继承调用方的工作目录、环境、标准输入输出，透传参数和目标退出码；其他文件统一按系统文件关联打开，不按 `.cmd`、`.vbs`、`.py` 等扩展名做分支。关联文件的参数解析和标准输入输出由对应处理程序决定。系统返回新进程句柄时等待并返回退出码；由已有应用接收文件时返回成功。实际能否打开取决于系统是否安装了对应的文件处理程序。该流程使用 [ShellExecuteEx 的文件关联及进程句柄机制](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow)。

所有目标统一使用 Windows 控制台标题接口：启动时以目标文件名作为初始标题，传递对应的启动标题，不检测终端品牌或目标程序名称。目标运行后可以自行更新标题；继承已有控制台时，运行结束恢复调用方原来的标题。没有控制台时跳过标题修改，不向标准输出写入标题控制码。

## 构建与打包

构建环境：Windows、PowerShell 7、.NET 10 SDK、CMake 3.24+、Visual Studio C++ 桌面工具集和 Windows SDK，以及 [NSIS 3.12+](https://nsis.sourceforge.io/Download)。ARM64 需要相应的 C++ 工具集。
安装 NSIS 后可以直接运行；便携编译器可设置环境变量 `NSIS_COMPILER` 指向 `makensis.exe`。脚本也会查找 `artifacts/tools/nsis-3.12/makensis.exe`。

```powershell
.\build.ps1                                       # 默认三种架构 × 两种类型，共六份 EXE
.\build.ps1 -Arch x64,arm64                       # 选择架构，默认 x86,x64,arm64
.\build.ps1 -PackageType FrameworkDependent       # 依赖系统运行时，文件名无类型后缀
.\build.ps1 -Arch x86 -PackageType SelfContained  # 自带运行时，后缀 -SelfContained
.\build.ps1 -Test                                 # 运行核心测试和本机匹配架构的应用测试
.\build.ps1 -Plan                                 # 只显示构建矩阵
.\build.ps1 -Version 0.2.0
.\build.ps1 -SkipInstaller                        # 仅生成发布目录
.\scripts\package.ps1                             # 使用已有发布目录重新打包六份 EXE
dotnet run --project tests/Pathman.Core.Tests -c Release  # 单独验证分号拆分与原始值读取
```

`-Arch` 和 `-PackageType` 都接受数组，省略时构建全部组合。普通包需要对应架构的 .NET 10 Desktop Runtime，自包含包不需要预装运行时。应用采用单文件发布，`bin` 只包含 `pathman.exe`。

`tests/gui-interactions.ps1` 和 `tests/installer-maintenance.ps1` 是隔离 Windows 虚拟机的回归脚本，需交互会话及测试安装目录 `C:\PathManTestApp`；前者的 `-PrepareFixture` 会重建测试分组和 `PATHMAN_*` 测试变量。请在可恢复检查点的虚拟机中运行，结束后恢复检查点。它们覆盖行内编辑、置顶／拖拽、自动滚动、运行检测、版本升级／覆盖、降级保护及配置保留。

`tests/gui-cleanup.ps1` 同样只允许在隔离虚拟机执行；先以管理员权限运行 `-PrepareFixture` 创建可恢复的测试 Path 和引用，再在普通用户交互会话运行脚本。它覆盖空草稿与空行删除、模式切换、引用跳转、清理预览／UAC 保存、健康页跳转及两个开关，运行时需确认测试虚拟机的 UAC。

`tests/gui-recursive-paths.ps1` 使用相同的隔离测试方式，覆盖递归展开、跨层移动、引用组嵌套、回环阻止、继承的系统变量提权保存、拖动自动滚动、引用着色、通知导航和 diff 滚轮。核心测试另外覆盖 OSC8 解析、内部链接校验、展开限制和 diff 重建。

`tests/gui-health-actions.ps1` 覆盖已有空行的未修改提交／取消、清空条目后的分号处理、健康问题上下文、忽略与恢复、按实际来源删除重复项、类型修正及 UAC、双栏对比和新变量分组。它同样要求隔离虚拟机、管理员准备 fixture，以及普通用户交互测试。

`tests/gui-details-aliases.ps1` 覆盖健康详情的相关变量及修复按钮、同一窗口的管理员授权复用、别名完整操作、名称校验、禁用后的选择与编辑限制，以及垫片顺序修复。它复用 `gui-health-actions.ps1` 的 UI Automation 辅助函数，两个脚本需放在虚拟机的 `C:\PathManFeaturesTest` 中。

`tests/gui-elevation-session.ps1` 使用相同辅助函数，验证取消 UAC 不写入且保留草稿；加 `-Elevated` 时需在管理员交互会话运行，验证管理员标题与直接保存。各项 GUI 脚本依次执行，避免共享窗口、鼠标和测试数据互相干扰。

`tests/gui-health-alias-regressions.ps1` 覆盖健康详情引用链与整行标红、左右列编辑边界、别名名称校验、空／无效目标存储、浏览期间与取消后的配置不变、选择非 EXE／无后缀文件、删除前不写入临时配置、点击空白与键盘失焦自动保存、无弹窗的页面切换／刷新／关闭，以及管理员授权后的标题更新。`tests/shim-file-associations.ps1` 在隔离虚拟机中验证批处理及任意扩展名的系统文件关联调用；测试关联使用独立临时名称并在结束时移除。

`tests/shim-terminal-title.ps1` 使用普通控制台探针验证修改前后的标题、启动标题、目标程序自行改标题、调用方标题恢复及退出码，并检查 Windows Terminal 实际可见的标签文字。夹具位于虚拟机的 `C:\PathManTitleTest`，`before`／`after` 各包含对应版本的 `terminal-alias.exe` 与 `.shim`，目标为使用 .NET Framework C# 编译器编译 `tests/shim-console-probe.cs` 得到的 `目标 程序.exe`；控制台探针本身不依赖 PowerShell 或特定终端。

## 使用

安装后先在“程序别名”页启用程序别名，再重新打开终端。以下别名示例使用默认安装路径下的 PowerShell 7，可按实际情况替换目标程序路径：

```powershell
pathman layout
pathman shim add pm-pwsh "C:\Program Files\PowerShell\7\pwsh.exe"
pathman shim list
pm-pwsh --version
pathman shim refresh
pathman shim remove pm-pwsh

pathman background start
pathman background status
pathman background stop
pathman startup enable
pathman startup status
pathman startup disable
```

GUI 使用 Win11 Fluent 控件与 DWM Mica 云母材质，内容延伸到标题栏，保留系统原生窗口按钮。侧边栏采用设置页的宽导航、彩色图标与选中样式；西文使用 Segoe UI Variable，中文使用微软雅黑 UI，标题采用常规字重。旧版 Windows 使用主题背景作为回退。变量管理的两栏内容等宽，左右列表均为 24 逻辑像素的紧凑行，文字垂直居中，选中时显示矩形蓝底白字。分类行没有常驻背景色，变量名略向右缩进。用户变量与系统变量之间的分界线可以上下拖动，调整两块列表的高度，右侧编辑区继续覆盖两块列表的整体高度。

分类规则：

- 路径变量：名称以 `PATH` 结尾（不区分大小写，且不要求下划线），包含多个有效路径；或只包含一个路径，但在相应作用域 PATH 中被纯引用。`%变量名%` 和 `%变量名%\` 都属于纯引用；`%变量名%\bin`、引号包裹的引用不属于纯引用。空条目不计为路径数量，分类检查不会改写原值。
- 系统变量：仅在系统作用域显示，包含 Windows 内置且通常无需手动修改的变量。名单位于 `src/Pathman.Core/EnvironmentVariables/Defaults/windows-variables.json`，以微软文档为来源；不把 USMT 专用 CSIDL 宏、CMD 动态伪变量或经常修改的 PATH、PATHEXT、TEMP、TMP 当作此类。用户作用域不显示此默认分类，自定义分组不受影响。
- 其他变量：未匹配以上规则的变量。PATHEXT 是分号列表，但不属于路径变量。
- 外部变量：启用监控后显示，包含监测到被外部程序新增或修改的变量。

分组定义由默认 JSON 和 `%LocalAppData%\PathMan\environment.json` 中的 `groups` 列表驱动，界面按配置生成，分类种数没有写死在代码中。新建分组只影响所在作用域；删除分组会保留变量并移入默认分组。默认接收未分类变量的分组需保留。

“用户变量”和“系统变量”标题右侧保留新建图标，点击展开标准菜单，使用对应标题的作用域。变量／分组行末提供置顶、编辑和删除；左侧双击名称或按 F2 开始行内编辑，Enter／失去焦点提交，Esc 取消，名称无效时留在输入框内提示。右栏标题是所选变量或分组的名称；选择分组时显示组内变量及其值，双击右侧变量进入该变量的编辑区，行尾的编辑按钮仍可改名。

新建环境变量窗口继承所点标题的用户／系统作用域；下拉框选择这个作用域中的分组，默认“其他变量”，保存所选归属，不再重复询问作用域。

选择变量时普通单值显示为文本，路径类变量、PATHEXT 和含 `;` 的变量显示为列表，单条路径也可使用引用跳转，两种编辑区的首字符位置一致。连续和末尾分号对应的每个空条目都有独立行，显示淡色“（空条目）”。列表行不再放编辑和删除图标，使用框外按钮或双击编辑；“新建”在列表末尾生成空行并立即输入，填入内容后 Enter／失焦保留，空草稿失焦或 Esc 则移除；将非空条目清空，或在已有空条目中输入后再清空，会删除这一行及对应的分隔位置。已有空条目未更改时，Enter／失焦／Esc 都保留它。“浏览…”单独选择文件夹。“复制”下面的“删除”移除选中条目，右下角“文本模式”／“多行模式”直接切换原始分号文本与列表，普通单值也可切换，切换本身不会改动值。删除最后一行后保存为空值，不会重新生成空白行。列表操作和文本编辑先暂存，点击保存才会写入；切换变量或关闭时会提示未保存的更改。复制已选条目取得单项，没有选中条目时复制完整值，未编辑的空项、重复项、空白和顺序均保留。路径变量行内有 `%变量名%` 引用时，行尾显示跳转按钮；多个引用通过菜单选择目标，按当前作用域解析用户覆盖。

路径列表中的纯引用（例如 `%DEVELOP_PATH%` 或 `%DEVELOP_PATH%\`）可像分组一样递归展开；仅展开名称以 `PATH` 结尾的已保存变量，回环和过深的引用停止展开。路径条目与引用组可以互相排序，也可以拖入其他引用组，原位置保留空位，浮层跟随鼠标，目标显示高亮或细插入线，边缘支持按距离加速滚动。拖动不跨越用户／系统作用域，产生回环的位置不能放置。编辑从用户 Path 展开的系统变量仍会在保存时请求管理员权限；保存会验证并写入各条目的实际所属变量，展开操作本身不展开写回原始值。所有值中的 `%变量名%` token 使用圆角淡黄色背景（由 `#DDF4FF` 只改色相得到），原生文本编辑仍保留光标、输入法和撤销。

“健康检测”参考 [Nextcloud 管理概览的检查汇总](https://docs.nextcloud.com/server/latest/admin_manual/configuration_server/security_setup_warnings.html)，展示引用回环、未定义变量、展开后的重复项、空条目与展开限制，并给出建议和定位链接。空条目显示实际所属变量、行号和上下行；可单独删除空行。重复项按展开后的来源提供删除按钮，只提供删除后仍保留全部有效路径的选项；复用的引用不会误删共享定义中的所有副本。修复前验证原值与类型，写入时沿用冲突校验和系统变量 UAC；保存后重新检测。“查看详情”在原页面左侧展示相关环境变量及原始条目，右侧展示忽略与修复按钮；定位链接进入变量管理，返回按钮回到检测概览。

检测规则位于 `src/Pathman.Core/EnvironmentVariables/HealthChecks`，每项实现 `IEnvironmentHealthCheck`。新增公开、无参数构造的检查类会自动加入默认检测管线；设置唯一的 `Id`、分类 `Title`，在 `Check(EnvironmentHealthContext)` 返回问题即可。界面按问题的 `Category` 生成分类，无需增加界面分支。也可通过 `EnvironmentHealth.Analyze(..., checks: [...])` 注入检查实例，使用 `DelegateHealthCheck` 包装检查函数。修复建议携带源值快照，在应用时重新验证，避免覆盖检测后的外部修改。详情显示单独使用问题行的引用来源，递归保留到出错位置的引用链，排除无关的依赖变量；问题行整行使用红色背景。

系统变量的首次写入请求 UAC，随后由同一窗口复用专用管理员助手。助手只接受系统环境注册表操作，连接校验双方进程及随机凭据；用户配置仍由普通窗口保存。关闭窗口或闲置 15 分钟后助手退出，之后再次写入需要重新授权。取消 UAC 保留未保存的编辑。普通窗口完成授权后，标题立即改为“管理员操作已授权”；助手退出后恢复“以非管理员身份运行”。直接以管理员权限启动整个窗口时，标题显示“以管理员身份运行”。

系统变量引用仅在用户作用域可用的变量（含 `%USERPROFILE%` 等用户环境内置项）属于错误；如果存在同名系统变量，则按系统定义解析。含 `%变量名%` 引用却未使用 `REG_EXPAND_SZ` 的值也报错，可在内容不变的情况下修正类型。新建／保存含引用的值自动使用 `REG_EXPAND_SZ`；单独的字面 `%` 不触发转换。规则依据[微软环境构建顺序说明](https://devblogs.microsoft.com/oldnewthing/20231212-00/?p=109137)和[注册表类型文档](https://learn.microsoft.com/en-us/windows/win32/sysinfo/registry-value-types)。

应用打开及变量快照更新时自动检测，结果通过导航下方的通知提示；“忽略”只隐藏该份来源内容对应的问题，不修改环境值，可通过“显示已忽略”恢复提醒。来源内容或类型变化后会重新报告。关闭通知后，相同结果不会反复提醒，问题变化时会更新通知。通知支持红、黄、蓝、绿四种同饱和度／亮度的淡色，正文使用 OSC8 链接；`apppage:health` 和 `apppage:variables?scope=User&name=Path` 等内部链接在当前窗口导航。

右上角“清理”在页面内展示两种作用域的 Path 修改预览，点击“应用清理”才写入。预览使用左右双栏 diff，左侧“修改前”、右侧“修改后”，保留上下文、各自行号和 `@@` 区段标题；红色表示删除，绿色表示新增，不等长的修改块以空白单元格对齐。鼠标位于 diff 行上也能滚动整个预览。清理页面不另行运行健康检查，健康问题在健康检测页和侧栏通知中展示。系统 Path 保留已有的 Windows、System32、Wbem、WindowsPowerShell\v1.0、OpenSSH 目录及纯引用，将其他条目保留原文移入 `SOFTWARE_PATH`，名称已占用时依次使用 `SOFTWARE1_PATH`、`SOFTWARE2_PATH`，然后追加纯引用。不会重建缺失的系统目录或将任意 Windows 子目录都当作系统项；目录清单位于 `Defaults/windows-paths.json`，附有微软组件文档来源。用户 Path 只去重，不迁移软件路径。

清理按保存的作用域递归展开引用，以大小写无关的规范路径比较；直接条目与被引用路径重复时优先保留引用。被引用变量的内容保持原样，部分重叠但仍有独有路径的条目不会整项删除。应用前在 `%LocalAppData%\PathMan\backups` 保存含原始值和注册表类型的 JSON；同一作用域的迁移与 Path 更新一起验证、保存，源值或引用值变化后拒绝旧预览，写入失败回滚本批次。系统保存需要 UAC；两个作用域分别保存，部分完成时会在页面说明并重新生成预览。

置顶变量排在所属组前面，置顶分组排在所属作用域的分组前面；置顶状态和顺序保存到配置。变量可拖入同一作用域的其他分组，手动归属优先于所有自动分类规则。普通变量在组内按名称排列，置顶变量可以相互拖动排序；分组可在各自的置顶／非置顶区域内拖动排序。拖拽时原位置保留空位，浮层跟随鼠标，目标组高亮或显示黑色插入线；放到列表外取消，靠近列表上下边缘时自动滚动，离边缘越远滚动越快。

安装器自动使用系统支持的界面语言，不支持时使用英文，也支持 `/LANG=1033`（英文）或 `/LANG=2052`（简体中文）覆盖。安装与卸载从启动起共享全局互斥，覆盖所有架构、包类型和用户会话。向导始终使用一个窗口，选择所有用户安装后，仅在写入时请求 UAC 并使用隐藏的提权进程执行，确认提示使用“确定／取消”。

安装器沿用已有安装目录及安装范围，升级／覆盖保留用户分组、监控、自启、别名和 PATH 归属记录，并刷新垫片及跨卷副本；原先正在运行的后台程序在完成或取消维护后恢复。更换目录或安装范围须先卸载；卸载保留 `%LocalAppData%\PathMan` 用户数据。关闭运行中的 GUI 使用正常关闭请求，未保存的编辑仍可取消关闭，安装器可重试或取消；不会强制终止 GUI 或正在执行的别名命令。静默安装遇到运行中的程序会退出，避免弹出保存对话框。普通包仍会先检查对应架构的运行时。

“变量监控”页分为后台运行、用户变量和系统变量三组设置。“在后台运行监控程序”启动／停止独立的用户会话后台程序，通过注册表通知跟踪用户和系统环境变量，关闭 GUI 后继续运行；“登录时自动运行后台程序”独立控制当前用户 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，不立即改变运行状态。后台单实例，启动后建立快照，记录外部的新增、修改、删除，PathMan 自己的保存不会重复记为外部变化。“外部更改记录”以设置卡片进入页内表格，查看时间、作用域、变量名、更改前后原文，返回后仍在监控设置页。

监控规则分为“用户变量”和“系统变量”两张设置卡片，分类、自动整理、去重和迁移均独立保存。“将外部新环境变量归入‘外部变量’分类”只改变对应作用域在应用内的显示，手动分组仍有最高优先级；修改已有变量不会将它改归外部分类。关闭此项仍继续记录变化。两种作用域的自动整理均默认关闭，只启用其中一项不会整理另一种作用域。每张卡片的子选项分别控制删除外部新增的重复项、迁移外部新增项；用户侧归入 `EXTERNEL_USER_PATH`，系统侧归入 `EXTERNEL_PATH`，并在对应 PATH 引用它。已有项目保持原样；去重递归展开引用，用户 PATH 同时考虑前面的系统 PATH，部分重叠但有独有路径的引用不会整项丢弃。无法展开或可能形成回环的新增引用保留原位置并提示。自动整理前备份到 `backups/path-monitor-*.json`，保存时验证源值与引用值；关闭某一作用域的整理只取消该作用域的待办，另一项保持独立，监控记录继续覆盖两种作用域。旧版共用的分类、整理及子选项会分别迁移为两份独立设置。普通后台可直接整理用户 PATH；系统 PATH 需要管理员权限，权限不足时保留待办并在应用内提供“授权并整理系统 PATH”，已有授权时继续处理。

手动清理预览比较清理前后递归展开的有效搜索顺序，忽略大小写、路径末尾分隔符和后续重复副本；顺序改变时在双栏 diff 上方提示可能影响命令／版本选择。引用无法完整展开时提示无法确认顺序。自动整理导致顺序改变时通过监控页与侧栏通知说明，保留备份和外部原始更改记录。

“程序别名”页的“启用程序别名”将垫片目录添加到用户 Path 的最后一个条目，移除同目录的旧条目，系统 Path 保持不变。Windows 将用户 Path 接在系统 Path 之后，因此别名排在其他命令之后。关闭开关仅移除垫片目录，不删除别名文件；新终端使用更新的 Path。新安装默认不再自动加入垫片目录，升级保留现有开关状态。
点击别名行左侧编辑名称，点击右侧编辑目标程序路径，输入框各占对应的一列；Enter、点击其他位置或键盘失焦都会保存，Esc 取消。新建输入合法名称后即保留别名，目标可以为空、不存在或包含非法路径字符；是否能够启动由垫片在调用时判断。目标按原文编码保存，兼容读取旧版配置；缺失或损坏配置的别名仍会列出并允许修复。名称校验涵盖非法字符、保留设备名、末尾空格／句点和长度限制；重命名同时移动 EXE 与配置，冲突时保留原别名。浏览可选择任意类型的文件，打开选择框期间不保存，选择文件后才写入所选路径；取消后保留当前输入继续编辑。删除直接移除别名，不先保存当前输入。切换页面、刷新或关闭窗口时直接保存，不弹出未保存提示。非法名称或保存失败时保留输入并说明原因。“复制”复制命令名，其右键菜单可复制目标路径。开关关闭或外部移除垫片目录后，六个操作按钮与行内编辑禁用，仍可选择。健康检测会警告垫片目录不在用户 Path 最后一项、重复出现或误放在系统 Path；可安全移动时提供“移到用户 PATH 末尾”操作。
带单引号的别名在 PowerShell 中要使用调用运算符和双引号，例如 `& "p'w'sh"`。

可用 `pathman --data-root <目录> ...` 隔离别名数据。测试在临时目录执行，不修改真实 PATH 或自启设置。
