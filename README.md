# PathMan

Windows 环境变量、程序别名与环境版本管理器。

> **pre-alpha**：功能、命令、配置格式与界面可能调整。

## 功能

- 环境变量管理：编辑用户和系统变量，支持分组、置顶、拖拽、分号列表和递归引用。
- 健康检测：检查引用回环、未定义变量、作用域错误、注册表类型、重复项、空条目和垫片目录顺序，提供定位与修复操作。
- PATH 清理：展开引用后去重，整理系统软件路径，提供双栏差异预览与原始值备份。
- 程序别名：通过垫片调用程序或关联文件，管理名称和目标路径。
- 版本管理：使用桌面界面或 CLI 登记版本，并切换环境变量的当前值。
- 变量监控：实时读取环境变量变化，记录外部修改，按作用域配置后台自动整理。

桌面界面采用 Win11 Fluent 风格和 Mica 云母材质，支持系统浅色与深色主题。

## 安装

安装包提供 `x86`、`x64`、`arm64` 三种架构，每种架构有两种类型：

| 文件名 | 运行时要求 |
| --- | --- |
| `PathMan-<版本>-<架构>.exe` | 对应架构的 .NET 10 Desktop Runtime |
| `PathMan-<版本>-<架构>-SelfContained.exe` | 自带运行时 |

安装器使用系统支持的界面语言，不支持时使用英文。可用 `/LANG=1033` 指定英文，`/LANG=2052` 指定简体中文。

向导提供当前用户和所有用户两种安装范围，并可设置安装目录、开始菜单与桌面快捷方式。所有用户安装需要管理员权限。默认目录：

- 当前用户：`%LocalAppData%\Programs\PathMan`
- 所有用户：`%ProgramFiles%\PathMan`

同一时间可运行一个安装或卸载程序。安装器支持覆盖安装与升级，保留用户配置并刷新垫片。检测到主窗口或后台程序正在运行时，向导内会提示保存工作；点击“继续”后终止这些进程，并等待 CLI 任务完成。安装完成后恢复此前运行的后台程序。通过别名启动的程序可以继续运行。

覆盖安装沿用已登记的目录和安装范围；更换目录或范围时先卸载。卸载保留 `%LocalAppData%\PathMan` 中的用户数据。

## 版本管理 CLI

`pathman` 提供以下命令：

| 命令 | 用途 |
| --- | --- |
| `pathman list [项目]` | 查看版本项目、绑定变量、PATH 引用和当前值 |
| `pathman add <项目> <版本> <值> [--variable <变量名>] [--type User\|Machine] [--replace]` | 登记或更新版本 |
| `pathman switch <项目> <版本>` | 将版本值写入绑定的环境变量 |
| `pathman delete <项目> [版本]` | 删除项目或版本配置 |

```powershell
pathman add java 8 "D:/Java/jdk-8/" --variable JAVA_HOME --type Machine
pathman add java 25 "D:/Java/jdk-25/"
pathman add java lts "D:/Java/jdk-25/"
pathman list
sudo.exe pathman switch java 25
pathman delete java 8
pathman delete java
```

首次登记项目时指定 `--variable`。`--type` 默认为 `User`，同一项目的后续版本沿用其绑定。已有版本可用 `--replace` 更新。版本值可以是路径或普通文本，允许登记尚不存在的目录。

`add` 保存版本配置；`switch` 写入实际环境变量。`delete` 删除版本配置，保留环境变量及其当前值。

`list` 从注册表读取当前值。多个标签可以指向同一值，例如 `25` 和 `lts`；`RefsByPATH` 表示 PATH 是否直接或间接引用目标变量。

CLI 使用当前进程权限。修改系统变量需由调用者提供管理员权限，例如使用 `sudo.exe` 或管理员终端；权限不足时命令报错退出。

## 桌面界面

### 变量管理

左栏分别显示用户变量和系统变量，可拖动分界线调整两个区域的高度。变量按分组排列，选中分组时，右栏显示组内变量；双击右栏变量进入其编辑区。

标题旁的加号用于新建分组或变量。变量与分组行末提供置顶、重命名和删除。双击名称或按 F2 编辑，Enter 或失焦提交，Esc 取消。

默认分类：

| 分类 | 规则 |
| --- | --- |
| 路径变量 | 名称以 `PATH` 结尾，包含多个路径；或包含单个路径并被相应作用域的 PATH 纯引用 |
| 系统变量 | Windows 内置且通常无需修改的变量，仅在系统作用域显示 |
| 其他变量 | 未匹配其他分类的变量 |
| 外部变量 | 启用对应监控选项后接收外部新增变量 |

支持自定义分组，手动归属优先于自动分类。置顶变量排在所属组前部，置顶分组排在所属作用域前部。变量可拖入其他分组，分组及置顶项目支持拖动排序；拖到列表边缘时自动滚动。

普通值可使用文本编辑，PATH、PATHEXT 和其他分号列表可逐行编辑。分号对应的空条目会显示为空行。新建条目后直接输入，空白草稿在取消或失焦后移除；已有条目编辑后清空时删除该行，未修改的空行会保留。文本模式与多行模式可随时切换。

`%变量名%` 引用以黄色背景标识。路径行的跳转按钮可定位被引用变量。纯引用形式包括 `%TOOLS_PATH%` 和 `%TOOLS_PATH%\`；引用已保存的路径变量时，可递归展开和拖动其条目。保存会写入各条目的实际所属变量。

变量值的更改先暂存，点击“保存”写入注册表，点击“撤销”恢复。切换变量或关闭窗口时会提示处理未保存的更改。含引用的值使用 `REG_EXPAND_SZ`。

主窗口实时监听环境变量。未编辑时，外部更改直接更新显示；存在未保存编辑时，右栏展示差异：红色为外部删除，绿色为外部新增，蓝色为本地修改。可选择撤回外部更改、清理外部更改，或在本次编辑期间启用临时自动清理。

### PATH 清理

右上角“清理”打开双栏差异预览，确认后点击“应用清理”。

- 用户 PATH：展开引用后去重。
- 系统 PATH：保留 Windows 系统目录和纯引用，将软件条目归入 `SOFTWARE_PATH`，并添加相应引用；名称已占用时使用 `SOFTWARE1_PATH`、`SOFTWARE2_PATH` 等。
- 直接条目与被引用的路径重复时，优先保留引用；被引用变量的内容保持原样。

预览会检查有效搜索顺序，顺序变化时提示可能影响命令和程序选择。写入前备份原值与注册表类型；源值或引用发生变化时，需要重新预览。

### 健康检测

启动和变量快照更新时自动检测，问题通过侧栏通知提示。检测范围包括引用回环、未定义变量、空条目、展开后的重复项、系统变量对用户变量的引用、注册表类型和垫片目录顺序。

“查看详情”展示相关变量、引用链及问题行，并提供适用的修复操作。空条目显示上下文，重复项可按实际来源选择删除。系统变量引用仅在用户作用域定义的变量属于错误；含引用的值应使用 `REG_EXPAND_SZ`。

“忽略”隐藏相同来源内容的问题，可通过“显示已忽略”恢复。来源内容或类型变化后会重新报告。

### 程序别名

“启用程序别名”将垫片目录放到用户 PATH 末尾。关闭开关会移除该 PATH 项，保留别名配置。PATH 更改在新终端中生效。

支持新建、重命名、目标编辑、浏览、复制和删除。点击名称或目标路径可分别编辑对应列；Enter、失焦或切换页面时保存，Esc 取消。开关关闭时可以选择条目，编辑操作禁用。

别名名称须符合 Windows 文件名规则。目标可以是完整路径，也可以是 PATH 中的文件名，例如 `powershell.exe` 或 `npx.cmd`。目标路径允许为空、不存在或无效，调用时由垫片报告错误。浏览可选择任意文件类型；复制按钮复制命令名，其右键菜单可复制目标路径。

原生可执行程序继承调用方的工作目录、环境和标准输入输出，并透传参数与退出码。关联文件交给 Windows 的默认处理程序打开；参数、输入输出和进程退出行为取决于对应处理程序。目标启动时使用目标文件名作为控制台初始标题，结束后恢复调用方标题。

带单引号的别名在 PowerShell 中可通过调用运算符执行，例如 `& "p'w'sh"`。

### 版本管理

左栏为项目名称和目标变量（含作用范围），右栏为版本名称和变量值。单击选择，双击项目名称或版本字段编辑；双击目标变量打开选择器，同时设置变量和作用范围。

左侧加号和右侧“新建”创建空白行。Enter 或失焦保存配置，Esc 取消，空白草稿在失焦后移除。栏外提供新建、重命名、编辑、浏览、复制、删除和切换操作。浏览选择版本目录，复制取得选中版本的值；点击“切换”才修改实际环境变量。

项目可以先登记名称和版本，再绑定目标变量。删除项目或版本保留环境变量当前值。桌面界面与 CLI 共用配置。

PATH 不能作为版本目标。内置系统变量按名称清单限制，默认不可选；“关于 → 高级设置”中的开关可允许选择，并显示风险警告。此规则同时适用于 CLI。自定义分组不影响目标限制。

### 变量监控

后台程序运行需要同时开启“在后台运行监控程序”和“登录时自动运行后台程序”。关闭后台运行会关闭登录自启，其余选项保留并置灰。主窗口的只读监听独立运行。

用户变量和系统变量分别配置以下选项：

- 将外部新增变量归入“外部变量”分类，仅影响应用内显示。
- 自动整理 PATH，并分别控制删除外部新增的重复项和迁移外部新增项。
- 排除系统环境编辑器或 PowerToys 修改的变量。

用户外部路径归入 `EXTERNEL_USER_PATH`，系统外部路径归入 `EXTERNEL_PATH`。整理会保留已有项目，递归检查引用和重复路径；无法安全处理的项目保留并提示。修改前生成备份，搜索顺序变化时给出提醒。

“精确识别修改来源”需要管理员权限。启用后记录写入进程路径和命令行，供编辑器排除规则使用；来源无法确认时保留原值。普通后台可以整理用户 PATH，系统 PATH 整理需要管理员授权。

通过“外部更改记录”卡片查看变更时间、作用域、变量名、更改前后内容及写入进程。

## 权限与数据

GUI 首次修改系统变量时请求 UAC，并由当前窗口复用管理员助手。关闭窗口或闲置 15 分钟后，助手退出。取消授权会保留编辑内容。标题栏显示进程权限或管理员操作授权状态。

用户配置保存在 `%LocalAppData%\PathMan\environment.json`，包括分组、置顶、版本、监控选项和变更记录。环境变量值保存在 Windows 注册表，修改备份位于 `%LocalAppData%\PathMan\backups`。

### 安装目录

```text
PathMan\
├── PathMan.exe
├── LICENSE
├── bin\
│   └── pathman.exe
└── internal\
    ├── PathMan.Service.exe
    ├── PathMan.Shim.exe
    ├── PathMan.SetupActions.dll
    ├── install.ini
    └── Uninstall.exe

%LocalAppData%\PathMan\
├── environment.json
├── backups\
└── shims\
    ├── <别名>.exe
    └── <别名>.shim
```

同卷时，别名硬链接到安装目录中的垫片；跨卷时，在 `%LocalAppData%\PathMan\internal` 保存一份垫片副本，别名硬链接到该副本。LocalAppData 所在卷需支持硬链接。安装目录可通过卸载登记中的 `InstallLocation` 解析。

## 模块

| 模块 | 技术 | 职责 |
| --- | --- | --- |
| Pathman.Core | C# / .NET 10 | 环境变量、版本配置、分类、检测、监控与别名管理 |
| Pathman.Gui | C# / WPF | 桌面界面 |
| Pathman.Cli | C# | 版本管理命令行 |
| Pathman.Service | C# | 用户会话后台监控与安装维护 |
| Pathman.Shim | C++20 / Win32 | 程序别名调用 |

`Pathman.Service` 以用户会话中的普通后台进程运行。

## 构建与测试

构建环境为 Windows、PowerShell 7、.NET 10 SDK、CMake 3.24+、Visual Studio C++ 桌面工具集、Windows SDK 和 [NSIS 3.12+](https://nsis.sourceforge.io/Download)。ARM64 构建需要对应的 C++ 工具集；`-Test` 需要 PowerShell 7.6+。

便携 NSIS 编译器可通过环境变量 `NSIS_COMPILER` 指向 `makensis.exe`。

```powershell
.\build.ps1
.\build.ps1 -Arch x64,arm64
.\build.ps1 -PackageType FrameworkDependent
.\build.ps1 -Arch x64 -PackageType SelfContained
.\build.ps1 -Test
.\build.ps1 -Plan
.\build.ps1 -SkipInstaller
.\scripts\package.ps1
```

`-Arch` 接受 `x86`、`x64`、`arm64`，`-PackageType` 接受 `FrameworkDependent`、`SelfContained`。两个参数都接受数组，默认构建全部六种组合。

安装包位于 `artifacts\setup`，发布目录位于 `artifacts\publish\win-<架构>\<类型>`。同名 `.exe.json` 文件记录架构、包类型和 SHA-256。

核心测试可单独运行：

```powershell
dotnet run --project tests/Pathman.Core.Tests -c Release
```

`build.ps1 -Test` 运行核心测试与本机匹配架构的运行时测试。[tests](tests/) 中的桌面、CLI、监控和安装器回归脚本用于隔离 Windows 虚拟机。根据脚本参数准备测试数据，在交互会话中运行，完成后恢复检查点。
